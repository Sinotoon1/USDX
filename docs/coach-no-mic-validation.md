# 无麦克风练习回归

## 根因与行为

玩家的 `TCaptureBuffer` 总会创建，但只有分配了可打开的输入设备才具有
`AudioFormat`。练习模式每 40ms 直接读取这个格式的采样率；在没有设备的原生
运行中，`UNote.NewNote → TCaptureBuffer.AnalyzeBuffer` 触发访问异常。

修复在采样率读取前处理缺少格式 / 无效采样率，保留无音高状态。停止采集时
释放格式、清空音频和音高；设备打开失败时撤销通道关联，避免看起来仍在采集。
停止只清理分析状态，保留 `LogBuffer` 供既有 `Finish/LogVoice` 保存录音；
下一次开始才清空整段录音，避免影响“保存回放”设置。
练习页面显示中英双语的无麦克风说明，不再叠加阻断式玩家配置弹窗。试听、
歌词、切句、重唱、循环、暂停和返回保持可用；已连接输入仍按原流程分析。
游玩模式的玩家配置提示和计分规则未改变。

## 自动化

```powershell
python -m unittest discover -s test/coach -p 'test_*.py' -v
python tools/build_studio_theme.py --check
```

81 项 Python 检查包含采集边界与 HUD/生成器接线约束。它们不能替代执行 Pascal。
`test/coach/coach_capture_test.pas` 直接执行生产 `URecord`，不替换音高检测或
采集缓冲区实现。测试设备的 `Start/Stop` 结果可控，提供确定性的打开失败与重试。

`build_capture_project.py <已 configure 的工程目录>` 在 `src` 生成临时 DPR，
沿用主程序的显式单元顺序，避免大型循环依赖导致的错误 PPU 复用。
构建时使用独立、全新的单元输出目录，先 `fpc -Cn` 再链接，避免混用历史缓存；
生成的 DPR / 输出目录不进入版本控制。Windows CI 在完整游戏编译后执行此测试。
CI 同时发布小型原生更新与完整便携包。更新附带完整游戏资源 / DLL 的 SHA256
清单；复用旧版资源前逐项验证，避免每次二开重复下载未变化的字体和运行库。

实际断言：

- 未分配输入、练习 / 游玩分析不解引用空格式。
- 已连接输入的 440 Hz PCM 仍得到有效音符。
- 清空 / 停止不会复用上一首的音高、格式。
- 设备打开失败后通道、格式、音高均不可用。
- 重新成功打开后，新的真实 PCM 缓冲区恢复 440 Hz 的连续音高识别。

## 原生界面回归

私有 Xvfb + 原生 SDL/OpenGL，隔离配置、分数库、ALSA 环境，不操作用户桌面。
无麦克风场景使用不存在的 ALSA 默认设备，并以 PortAudio 枚举结果 **0 个采集
设备**为前置检查；不是用零采样虚拟麦克风冒充“没有麦克风”。修复前实际复现
访问异常，修复后检查连续播放、句切换、重唱、循环、暂停 / 继续、Esc 返回。

另用可枚举的虚拟输入验证已分配与未分配通道的分支。该夹具与确定性 PCM 测试
用于回归软件状态，不代表实体麦克风或实际音频延迟的测量结果。

原始日志中另有点歌机 `DrawPlaylist` 范围异常，本次未将其混作采集崩溃的堆栈，
也未扩展修改点歌机。新便携版复制既有配置、歌曲和分数数据，旧版目录保留。
